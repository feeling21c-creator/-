# RIVIAN FIELD CHECK
## 2단계 제작 설계서: DB·권한·화면 흐름 고정본

### 1. 이번 단계의 목적

이번 단계의 목적은 앱 코딩 전에 변하지 않아야 할 골격을 고정하는 것이다.  
앱의 본질은 체크리스트가 아니라 팀 공유형 현장 기록 시스템이다.

핵심 문장은 다음이다.

> 누가, 어느 현장에서, 어떤 공정을, 언제까지, 무엇을 확인했고, 어떤 문제가 남았는가.

이 문장에 답하지 못하는 기능은 1차 MVP에서 제외한다.

---

### 2. 1차 MVP 확정 범위

포함 기능:

1. 로그인
2. 권한별 화면 구분
3. 프로젝트 생성
4. 프로젝트별 팀원 배정
5. 공정별 체크리스트
6. 내 작업 화면
7. 사진 첨부
8. 특이사항 입력
9. 문제발생 등록
10. 수정 이력 저장
11. 전체 진행률
12. 공정별 진행률
13. 가전·가구 조회 외부 링크
14. 엑셀 다운로드

제외 기능:

1. 마감재 조회
2. 마감재 발주 관리
3. 고객 공유 화면
4. 카카오톡 알림
5. 문자 알림
6. AI 자동 요약
7. 고급 PDF 보고서
8. 협력업체 정산 연동

### 3. 권한 구조

| 권한 | 대상 | 첫 화면 | 핵심 기능 |
|---|---|---|---|
| owner | 대표 | 전체 프로젝트 위험 현황 | 전체 생성·수정·삭제·사용자 관리 |
| office_admin | 사무실 관리자 | 프로젝트별 진행률·이슈 | 프로젝트 관리, 작업 배정, 보고서 |
| site_manager | 현장관리자 | 담당 프로젝트 현황 | 담당 현장 전체 체크, 이슈, 사진 |
| field_worker | 현장 작업자 | 내 작업 | 자기 공정 체크, 사진, 문제 등록 |
| read_only | 외부 열람자 | 지정 프로젝트 보기 | 읽기 전용 |

현장 작업자에게 전체 메뉴를 보여주면 사용률이 떨어진다.  
작업자는 “오늘 내가 해야 할 것”만 보는 구조가 맞다.

### 4. 화면 흐름

#### 4.1 대표 화면

```
로그인
→ 홈
→ 전체 프로젝트 위험 현황
→ 문제발생 항목
→ 프로젝트 상세
→ 보고서 다운로드
```

#### 4.2 사무실 관리자 화면

```
로그인
→ 홈
→ 프로젝트 목록
→ 프로젝트 상세
→ 팀원 배정
→ 공정별 체크리스트 확인
→ 사진 검토
→ 이슈 관리
→ 엑셀 다운로드
```

#### 4.3 현장관리자 화면

```
로그인
→ 담당 프로젝트
→ 공정별 체크리스트
→ 작업자별 진행 확인
→ 문제발생 등록
→ 사진 업로드
```

#### 4.4 현장 작업자 화면

```
로그인
→ 내 작업
→ 체크 항목 선택
→ 완료 / 문제있음 / 사진찍기 / 메모
→ 저장
```

### 7. 체크 상태값

| 화면 표시 | 내부 상태값 | 의미 |
|---|---|---|
| 아직 안 함 | not_started | 확인 전 |
| 작업 중 | in_progress | 진행 중 |
| 완료 | done | 문제 없이 완료 |
| 보류 | on_hold | 일정·자재·고객 결정 대기 |
| 문제있음 | issue | 하자·누락·오시공 |
| 재확인 요청 | recheck_requested | 사무실 또는 관리자가 다시 확인 요청 |

---

### 8. 이슈 상태값

| 화면 표시 | 내부 상태값 | 의미 |
|---|---|---|
| 확인 필요 | needs_review | 아직 처리 방향 미정 |
| 처리중 | in_progress | 조치 중 |
| 보류 | on_hold | 외부 요인으로 대기 |
| 완료 | resolved | 해결 완료 |

### 9. 사진 저장 규칙

사진은 프로젝트 앨범으로 저장하지 않는다.  
반드시 체크 항목과 연결한다.

저장 정보:

```
프로젝트
공정
체크 항목
촬영자
촬영 시간
사진 설명
저장 경로
```

이 구조가 있어야 사무실에서 사진을 보고 현장 상황을 검토할 수 있다.

### 10. 가전·가구 조회 방식

1차 MVP에서는 내부 DB로 통합하지 않는다.  
현재 Netlify 앱을 외부 링크로 연결한다.

URL:

```
https://serene-buttercream-d97669.netlify.app/
```

2차에서는 다음 구조로 확장한다.

```
체크 항목 선택
→ 가전·가구 조회
→ 제품 선택
→ 현장 실측 입력
→ 설치 가능 여부 판단
→ 프로젝트에 저장
```

13. 대시보드 진행률 표시
14. 엑셀 다운로드
15. 가전·가구 조회 외부 링크 연결

### 12. 테스트 기준

1. 현장 작업자가 3분 안에 오늘 작업을 체크할 수 있는가
2. 사진 첨부가 10초 안에 가능한가
3. 사무실에서 문제 항목을 바로 찾을 수 있는가
4. 대표가 위험 현장을 30초 안에 파악할 수 있는가
5. 누가 체크했는지 이력이 남는가
6. 엑셀로 정상 출력되는가

---

### 13. 냉정한 보완 지점

1. 체크리스트 항목 292개는 현장 작업자에게 한 번에 보여주면 안 된다.
2. 공정별·담당자별로 자동 필터링되어야 한다.
3. 현장 작업자 화면은 버튼 수를 줄여야 한다.
4. 사진은 반드시 체크 항목 기준으로 묶어야 한다.
5. 마감재 모듈은 1차에서 제외하는 것이 맞다.
6. 고객 공유 화면은 데이터 안정화 이후 붙여야 한다.
7. 권한과 수정 이력은 1차부터 반드시 넣어야 한다.
